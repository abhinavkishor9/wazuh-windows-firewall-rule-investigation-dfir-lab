# Troubleshooting Notes

## Issue 1 — No Firewall Events Generated

### Cause

Windows Firewall Operational logging may not generate events for every firewall rule action.

### Resolution

Perform additional rule creation or modification and verify Event Viewer before investigating Wazuh.

---

## Issue 2 — Firewall Operational Log Empty

### Cause

The Firewall Operational log may not be enabled or may contain no recent activity.

### Resolution

Verify the Firewall log is enabled and refresh Event Viewer after modifying firewall rules.

---

## Issue 3 — No Results in Wazuh Discover

### Cause

Windows did not generate firewall events or indexing delay occurred.

### Resolution

Confirm the events exist in Event Viewer before troubleshooting Wazuh.

---

## Issue 4 — PowerShell Shows No Rule

### Cause

The firewall rule was successfully deleted.

### Resolution

Recreate the rule and validate it using:

```powershell
Get-NetFirewallRule | Where-Object {$_.DisplayName -like "*DFIR*"}
```

---

## Issue 5 — Verify Wazuh Agent Health

### Cause

Potential communication interruption.

### Resolution

Verify agent status:

```bash
sudo /var/ossec/bin/agent_control -i 001
```

---

# Lessons Learned

- Firewall logging depends on Windows configuration.
- Always validate Windows logs before investigating Wazuh.
- Event Viewer and PowerShell complement each other during DFIR investigations.
- Wazuh only collects events generated by Windows.
- Correlating multiple evidence sources produces a reliable investigation.
